Why Naive Top-K Retrieval Breaks First

  • Pure vector search misses exact keyword matches — IDs, error codes, product SKUs — that BM25 catches trivially.
  • Fixed-size chunking slices sentences mid-thought, so the "most similar" chunk is missing the clause that actually answers the question.
  • No reranking step means the top-k the LLM sees is ranked by embedding similarity alone, not the query's real intent.
  • Recall gets "fixed" by raising k instead of raising precision — the model drowns in more noisy context, not better context.

Fix It In This Order

  • 01Add BM25 (or another sparse/keyword method) alongside your vector index — hybrid retrieval, not vector-only.
  • 02Rerank the top ~50 hybrid candidates with a cross-encoder before the LLM ever sees them.
  • 03Chunk semantically — headings, paragraphs, code blocks — instead of a fixed character count.
  • 04Only widen the context window after retrieval precision is fixed. A bigger window just means more room for the wrong chunks.
